# auto-fix-qortal.sh — Improvements Plan

## Goal and corrected recovery policy
Fix recurring unnecessary bootstrapping while preserving intentional recovery.
The user's policy is to bootstrap when the validated primary reference is more
than 2,500 blocks ahead, or when height stalls at **any height**. `qortal.link`
is used only if `api.qortal.org` fails or returns an invalid height. There is no
genesis or minimum-height assumption. Active bootstraps and unknown API heights
must prevent database replacement.

## Implementation
- Compare jar bytes, validate complete downloads, correctly order versions,
  exclude prereleases, preserve custom builds when release metadata is unknown.
- Separate jar replacement/restart from database recovery; retain previous jar.
- Require timed height samples and a final recovery confirmation.
- Poll startup with periodic status messages and early completion instead of a
  silent fixed 35-minute sleep. Prevent recursive retries after an API failure.
- Match the installation's Java process; bound and verify shutdown.
- Stop before copying the DB, verify the backup, preserve rollback until launch,
  and delete script-owned full DB recovery copies after sustained confirmed startup.
  Restore originals when a failed launch creates a partial db. Reject custom
  repository paths. No full data folder backups are taken by this script.
- Close lock descriptor in Core children; preserve unrelated cron jobs.
- Preserve settings if jq, downloads, backup or merge fails.
- Bound small autogenerated settings/script/cron/logging backups to 10 per
  category, preserving latest-good settings and unrelated/manual files.
- Validate self-update syntax/revision; support AUTO_FIX_SELF_UPDATE=0 for testing.
- Ignore codegraph-cache in Git; update documentation and regression checks.

## Validation
Isolated Python/Bash regression tests, Bash syntax checks, ShellCheck and
`git diff --check`; no live Core recovery or deployment. Remote testing remains
with the user.
